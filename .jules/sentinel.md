## 2025-01-20 - [MathRenderer XSS via KaTeX configuration]
**Vulnerability:** The KaTeX engine inside `MathRenderer.svelte` was initialized with `trust: true`, allowing potentially dangerous command execution from user-supplied math markdown input. The rendered HTML was directly outputted to the DOM without sanitization (`{@html renderedHTML}`).
**Learning:** Math renderers like KaTeX often generate complex markup. If they're instructed to trust input in conjunction with unescaped HTML interpolation, it opens an avenue for XSS. Adding arbitrary DOM sanitization libraries (like `isomorphic-dompurify`) can introduce bloat and potentially break complex SVG/MathML outputs without careful configuration. KaTeX's `trust: false` is sufficient to mitigate execution risks within the rendering layer.
**Prevention:** 1) Disable unsafe KaTeX behaviors explicitly by setting `trust: false` in `katex.renderToString()`. This prevents the execution of arbitrary commands. 2) Avoid introducing external DOM sanitization libraries if the renderer’s native security options (e.g., `trust: false`) provide adequate protection.
